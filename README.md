# 🔐 SecureAuth — Human-Centered Two-Factor Authentication

**SecureAuth** is a security-focused Two-Factor Authentication (2FA) web application designed with both **Information Security** and **Human-Computer Interaction (HCI)** principles in mind.

It combines secure TOTP-based authentication with a clear, accessible, and user-friendly interface that helps users understand and manage their account security.

### 🌐 Live Demo

🚀 **[Open SecureAuth Live](https://secureauth-hci.vercel.app/)**

---

## 📌 Project Overview

SecureAuth demonstrates how modern authentication security can be implemented without making the user experience unnecessarily complicated.

Authentication is based on two independent factors:

1. **Something you know** — Username and password
2. **Something you have** — A 6-digit Time-Based One-Time Password (TOTP) generated by an authenticator app

Users must successfully complete both authentication stages before accessing protected areas of the application.

## 🔄 Authentication Flow

```text
User Registration
       ↓
Password Hashed
       ↓
TOTP Secret Generated
       ↓
QR Code Scanned
       ↓
2FA Enabled
       ↓
Login with Username + Password
       ↓
Password Verification
       ↓
OTP Verification
       ↓
Authenticated Session
       ↓
Security Dashboard
```

A full authenticated session is granted only after the required authentication factors have been successfully verified.

## 🔐 Security Controls

### Password Protection

Passwords are never stored as plain text. Werkzeug password hashing is used before credentials are stored.

### TOTP Authentication

Each user receives a unique TOTP secret during 2FA setup. The authenticator application and SecureAuth independently generate the same temporary code using the shared secret and current time.

Codes rotate approximately every **30 seconds**.

### TOTP Replay Prevention

SecureAuth tracks previously accepted TOTP time steps to prevent the same valid OTP from being reused.

### CSRF Protection

State-changing requests are protected using CSRF tokens generated and validated through Flask-WTF.

### Brute-Force Protection

The system uses multiple defensive controls, including:

* Failed password attempt limits
* Failed OTP attempt limits
* Temporary account lockouts
* IP-based rate limiting

### Session Security

Authenticated sessions include mechanisms for:

* Idle expiration
* Secure logout
* Invalidating other sessions
* Protecting authenticated routes

## 💾 Backup Codes & Account Recovery

During 2FA setup, SecureAuth generates **10 single-use backup codes**.

These codes allow users to regain access if their authenticator device becomes unavailable.

Each backup code:

* Can only be used once
* Is stored securely as a hash
* Can be regenerated through the security dashboard

## 🚀 Running Locally

### 1. Clone the Repository

```bash
git clone https://github.com/Muhammmad-Ashhad-Ansari/SecureAuth-HCI.git
cd SecureAuth-HCI
```

### 2. Install Dependencies

```bash
pip install -r requirements.txt
```

### 3. Configure Environment

Copy the example environment file:

```bash
cp .env.example .env
```

On Windows, you may also create `.env` manually from `.env.example`.

### 4. Start SecureAuth

```bash
python app.py
```

Then open the local address displayed by Flask in your browser.

## 📱 Setting Up Two-Factor Authentication

1. Create a SecureAuth account.
2. Continue to the 2FA setup screen.
3. Open Google Authenticator, Microsoft Authenticator, or another compatible TOTP application.
4. Scan the displayed QR code.
5. Enter the current 6-digit authentication code.
6. Verify and enable 2FA.
7. Save the generated recovery codes.
8. Log in using your password and authenticator code.

## 🧠 Project Motivation

Security mechanisms are often technically strong but difficult for ordinary users to understand.

SecureAuth explores how authentication security and good HCI design can work together.

The project aims to provide strong security controls while keeping important information, system status, recovery options, and authentication steps understandable to the user.

## ⚠️ Current Limitations

SecureAuth is primarily an **academic and demonstration project**, not a production identity platform.

Current limitations include:

* SQLite is used instead of a production-scale database
* TOTP secrets should be encrypted at rest in a production environment
* Password recovery can be expanded
* Rate limiting can be improved for distributed/proxy environments
* Production deployment requires additional infrastructure hardening
